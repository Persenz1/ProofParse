# 开发计划（2026-09-30 起）

目标：批量把科研 PDF 转成完整的 Markdown 与图片。公式要写成可靠的 LaTeX，工作尽量在本地完成。
整个流程由任意 agent 驱动，本地判断不了的项交回 agent，或交给用户配置的 API。
架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，候选模型见 [MODEL_SELECTION_PLAN](MODEL_SELECTION_PLAN_2026-09-30.md)。

原则：每一步先小规模跑通再扩大；模型的取舍只看金标准上的实测结果。

## 阶段 0　骨架冒烟（小规模）

- 用 Codex 已下载的 3 篇 arXiv 论文跑通 `gold build`，检查以下几项：
  - 颜色标记编译前后排版一致；
  - 公式框准确；
  - 数学字形覆盖完整。
- 用 1 篇 test_pdfs 里的论文走完整流程：MinerU + PP-FormulaNet M → status → tasks → export，修掉暴露出的问题。
- 完成标准：两条链路都能完整跑通，产物经人工抽查没有明显错误。

## 阶段 1　金标准扩充

- 由 Codex 把 arXiv 论文扩到 30–50 篇，覆盖不同学科、模板、单双栏，以及矩阵、多行对齐、代码和表格。
- 统计以下三类公式，并分析原因：未渲染的公式、宏无法展开的公式、未标注的数学字形。
- formula22-legacy 和 Zotero 出版社版 PDF 作为补充集，覆盖 arXiv 金标准的盲区（字体子集、编码损坏）。

## 阶段 2　公式识别模型横评

- 现有基线：UniMERNet-small、PP-FormulaNet M、PP-FormulaNet L。
- 按优先级新增适配器：Xiaomi-OCR-0、PaddleOCR-VL-1.6、OvisOCR2，之后是 GLM-OCR。每个模型用独立环境，按"模型文件夹"惯例存放。
- 用 `bench formula` 测以下几项：
  - 各模型的 strict / layout / loose 准确率；
  - 每一对模型"一致但都错"的比例；
  - 速度与峰值显存。
- 需要时补一个 CDM 类的渲染比对指标。

## 阶段 3　版面与区域

- 实现 `layout` 任务，即直接吃页面图片的版面模型。接入 PP-DocLayoutV3 和 TeleOCR，MinerU2.5-Pro 作为整页对照。
- 补一个版面基准：用金标准的公式框评估漏检、混入正文，以及图、表、代码的分类。
- 实现版面框的程序修正：按文字行、图片和矢量对象的边界吸附，解决夹行、混入正文、图外标注被裁的问题。

## 阶段 4　行内公式检测

- 用 `bench inline` 测字形级的精确率和召回率。
- 针对漏检改进规则，例如用正文字体排的数学（mathptmx 这类）。
- 用数据决定"文字层检测"和"模型检测"怎样合并。

## 阶段 5　定组合、校准规则

- 根据阶段 2–4 的结果，选主识别器和真正互补的补充模型，写入默认配置。
- 用"一致但都错"的实测比例决定哪些规则可以自动放行；精度不达标的规则改为升级处理。

## 阶段 6　升级路径与安装

- 用真实的少量任务测 agent 模式（包括弱模型）和 API 模式。API 调用需要用户逐次授权。
- 重写 `skill/` 安装引导。安装时让用户选择：
  - 安装哪些模型（显示体积和显存需求）；
  - 升级方式：agent、API 或不升级。
- 表格：结构校验流程，没校验的表格仍然以图片交付。

## 阶段 7　端到端验收

- 在没参与调试的新论文和出版社版 PDF 上跑完整流程，统计以下几项：
  - 最终公式错误率；
  - 未解决项的数量；
  - 交给 agent 的工作量；
  - 每篇耗时。
- 更新 README，发布新版本。
